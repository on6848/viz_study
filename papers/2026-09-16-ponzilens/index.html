PonziLens+: Visualizing Bytecode Actions for Smart Ponzi Scheme Identification

Xiaolin Wen, Tai D. Nguyen, Shaolun Ruan, Qiaomu Shen, Jun Sun, Feida Zhu, Yong Wang（2024） ・ arXiv:2412.18470
HCI Visual Analytics Blockchain Security

一言でいうと

ブロックチェーン上のスマートコントラクトの「バイトコード」を実行シミュレーションし、そこから得られる 実行パス（起こりうる処理の流れ）を、投資家や監査者が詐欺（Ponziスキーム）の兆候を目で確認 しながら判断できるように可視化するツールPonziLens+を提案した論文。

解きたかった問題

Ponziスキーム（自転車操業型の投資詐欺）は、新規投資者の資金を既存投資者への配当に回す典型的な詐欺の 仕組みで、スマートコントラクトの形でブロックチェーン上に多数存在する。既存の自動検知手法は (1) 決め打ちのルールや学習済みモデルに頼るため新しい手口に弱く（適応性の欠如）、 (2) 「なぜ詐欺と判定したか」の根拠を人間にわかる形で示せない（透明性の欠如）、という2つの課題があった。 投資家が自分で納得して判断できる、根拠が見える検知手法が必要とされていた。

提案手法の核心

まず、スマートコントラクトのバイトコードをシンボリック実行し、起こりうる実行パスを、 「情報を書き込む（Write）」「送金する（Payment）」「条件を確認する（Check）」「情報を読み取る（Read）」 という4種類の意味のある「アクション」の列に変換する。そのうえで、 投資者アドレスの記録・送金の実行・繰り返し（ループ）・過去の投資者への還元、という 4つの"Ponzi特徴"がアクション列の中でどう現れるかに注目し、3段階の粒度で可視化する：

  1. Path Feature Module（契約全体）: 全実行パスを4つのPonzi特徴でグループ化し、 パラレルセッツ図でその分布を俯瞰する。
  2. Path Grouping Module（パスグループ）: 選んだグループのアクション列を統合して要約し、 Ponzi特徴が現れる箇所（ループ・還元の繋がりなど）を強調表示する。
  3. Execution Detail Module（個別パス）: 1本の実行パスについて、ストレージへの 読み書きの詳細をアクション列とあわせて表示する（本デモでは省略、下記参照）。

触って理解する：架空のコントラクトの実行パスを辿る

架空の小さなスマートコントラクトを例に、Path Feature ModuleとPath Grouping Moduleを体験できます。 上のパラレルセッツ図でグループ（帯）をクリックすると、そのグループの典型的なアクション列が下に表示され、 ループや"還元"のつながりが視覚的にわかります。安全に見える経路から、典型的なPonziパターンまで 見比べてみてください。

※ ここで使っているコントラクト・実行パス・件数はすべて説明用に作成した架空のデータです （論文の実験対象・ケーススタディの実データではありません）。可視化の設計（配色・アイコン・強調表現）は 論文のFig. 4・Fig. 5に基づいていますが、実装は簡略化しています。特にExecution Detail Module （1本のパスのストレージ操作を二重らせん状に描く詳細ビュー）は本デモには含まれていません。

結果・インパクト

実際のPonziスキーム契約を含む2つのケーススタディと、専門家・一般投資家あわせて12名のユーザーインタビューで 評価。参加者全員が「これほど納得感のある根拠を示すツールは他になかった」と回答し、特に専門家は 監査業務での有用性を高く評価した。一方で、Path Grouping Moduleは他のモジュールよりやや評価が低く （7点満点中5.5点）、「強調表示されていないアクションの意味が分かりにくい」という指摘もあった。 一般投資家からは、Ponziスキームの典型パターンそのものへの知識不足を補うチュートリアルの充実が求められた。

限界・批判点

  • 実行パスの数が非常に多い複雑な契約では、パスの統合・グループ化を行ってもなお スケーラビリティの課題が残る（著者ら自身が言及）。
  • この手法が対象とするのはコード自体に不正なロジックが埋め込まれたPonziスキームであり、 PlusTokenのように詐欺のロジックがオンチェーン外にある事例には対応できない。
  • シンボリック実行の技術的な限界（ガス制限を考慮しないため実行不能なパスも探索してしまう、 Z3ソルバーが解けないパスを見逃す可能性がある等）が、検知の網羅性に影響しうる。

学び・所感

自動判定の結果だけを提示するのではなく、「なぜそう判断できるのか」を人間が追える形で可視化するという アプローチが印象的だった。特に、投資者のアドレスを書き込んだのと同じストレージスロットから 送金先を読み出しているかどうかを繋いで見せる（Rewarding特徴の可視化）ことで、 「新規資金をそのまま過去の投資者に回している」という詐欺の本質的な仕組みを、コードを読めない人にも 直感的に伝えられる点が優れていると感じた。セキュリティ・監査ツールにおいて「判定結果」ではなく 「判定の根拠となる構造」を見せるという設計思想は、他の不正検知の可視化にも応用できそうだ。
